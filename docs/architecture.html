Factory Inventory Management System

A demo full-stack application. A Vue 3 single-page app talks to a FastAPI backend over JSON. The backend serves sample data from JSON files that it loads into memory at startup. There is no database.

System architecture

The system has three tiers. The browser runs the Vue app. The Vue app calls the FastAPI server. The server reads from Python lists in memory, filled from JSON files when the process starts.

Solid arrows show runtime calls. The dashed arrow shows an offline step that a developer runs by hand.

Data flow

The main flow starts when a user changes a filter. Every view that watches the filters reloads its data from the API.

Step by step

  1. The user selects a time period, warehouse, category, or order status in the filter bar. client/src/components/FilterBar.vue
  2. The filter bar writes the value into a module-level ref. All components share these refs, because the refs live outside the composable function. client/src/composables/useFilters.js
  3. Each view has a watch() on the filters it uses. The watcher calls the view's load function. client/src/views/*.vue
  4. getCurrentFilters() maps UI names to API names (location → warehouse, period → month). api.js drops every value that is 'all' and sends the rest as query parameters. client/src/api.js
  5. FastAPI receives the request. apply_filters() matches warehouse exactly and matches category and status without case. filter_by_month() matches a month string such as 2025-03, or a quarter key such as Q1-2025, against order_date. server/main.py
  6. For typed endpoints, Pydantic validates the response against the response_model. FastAPI returns JSON. server/main.py
  7. The view stores the raw response in refs such as allOrders or inventoryItems. Computed properties derive totals, chart points, and table rows. Vue re-renders the page. client/src/views/*.vue

Startup flow

Backend

  • main.py imports mock_data.
  • mock_data.py reads all seven JSON files from server/data/.
  • The data stays in module-level lists for the life of the process.
  • uvicorn serves the app on 0.0.0.0:8001.

Frontend

  • main.js creates the router and mounts App.vue.
  • useI18n reads the saved locale from localStorage.
  • App.vue loads tasks; the active view loads its own data in onMounted.
  • The API base URL is fixed to http://localhost:8001/api.

Observations

These points came up while tracing the code. They help explain behavior that can look unexpected.

Missing backend endpoints. api.js calls /api/tasks (GET, POST, PATCH, DELETE) and /api/purchase-orders. The backend does not define these routes. The tasks modal shows only the mock tasks from useAuth, and the failed calls go to the console.
Unrouted view. Backlog.vue exists, but main.js has no route for it. The dashboard shows backlog data instead.
Reports bypasses the API client. Reports.vue uses the Options API and calls axios with a fixed URL. It does not use api.js or the global filters.
Year is fixed to 2025. The quarter map in filter_by_month(), the quarterly report, and the filter bar months only cover 2025.
Read-only, in-memory data. No endpoint changes data. A server restart reloads the JSON files.
Mock user. useAuth returns a fixed user profile on the client. There is no authentication.
